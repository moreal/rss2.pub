# ADR-0004: 핸들 정규화 정책

- Status: accepted (2026-07-26), amended (2026-08-23: 콘텐츠 모드를 해시에 포함)
- Context: docs/PLAN.md §4 (2026-07 조사 — RFC 7565, Mastodon/Misskey/Pleroma/Lemmy 소스)

## 결정

피드 액터의 핸들(username)은 canonical feed URL과 콘텐츠 모드로부터 결정적으로
생성한다:

1. NFKC → 소문자 → `[a-z0-9]` 밖 문자를 `_`로 치환
2. `_` 연속 붕괴, 선두/말미 `_` 제거
3. 앞 22자로 절단(말미 `_` 재정리) + `_` + 해시 기반 base36 앞 7자를 **항상**
   덧붙인다 — 길이 초과 여부와 무관하게 매 핸들에 적용. 해시는 SHA-256(canonical
   URL)이며, `fullContentEnabled`가 참이면 SHA-256(canonical URL + 모드 마커)로
   바뀐다(ADR-0009 개정).

문자셋 `^[a-z0-9_]+$`, 최종 길이 최대 30자(22+1+7).

**2026-08-23 개정**: `Handle.fromFeedUrl`이 `fullContentEnabled`(기본값 `false`)를
두 번째 인자로 받는다. 같은 URL이 teaser/전문 두 모드로 각각 등록되면(ADR-0009)
스템은 같지만 해시 입력이 달라 서로 다른 핸들이 나온다 — 스템 부분에 `full` 같은
표식을 넣지 않은 이유는, 해시만으로 두 모드를 항상 구별 가능하게 만드는 것으로
충분하고(핸들의 역할은 안정적 식별자이지 사람이 읽는 설명이 아님), 기존 22자 절단
로직에 표식용 여유 공간을 새로 마련하는 복잡도를 피하기 위함이다. 모드를 사람이
읽을 수 있게 알리는 역할은 액터 프로필 설명(`render.ts`)과 웹 UI 배지가 맡는다.
기본값 `false`는 기존(ADR-0009 이전) 모든 호출부가 오늘과 동일한 핸들을 계속
도출하게 만든다 — 배포된 핸들이 이 개정으로 바뀌지 않는다.

## 근거

- `[a-z0-9_]`는 조사한 모든 구현체(Mastodon 원격/Misskey/Pleroma/Lemmy)가 수용하는
  교집합. `.`과 `-`는 로컬 생성 불가·원격만 관용되는 2급 문자라 배제.
- Misskey는 원격 username 128자 초과 시 액터 자체를 거부 — 30자는 안전 마진이 크고,
  마스토돈 로컬 한도(30)와 같아 네이티브 계정처럼 보인다.
- 해시 suffix를 항상 붙이면 절단으로 인한 충돌뿐 아니라, 정규화가 손실적이라
  발생하는 짧은 스템 충돌(예: `a-b.com`과 `a.b.com`)까지 결정적으로 회피한다
  (같은 URL → 항상 같은 핸들, 다른 URL → 항상 다른 핸들). 조건부 적용이었을 때는
  22자 이하 핸들만 이 충돌에 노출되어 있었다.
- 소문자만 발급: Mastodon/Misskey는 대소문자 무시 조회를 하므로 혼합 케이스는 이득 없이
  중복 정체성 혼란만 만든다.
